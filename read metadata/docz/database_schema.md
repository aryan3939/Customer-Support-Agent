# Database Schema & Retrieval Mechanics

The system utilizes a "Database-as-Code" approach. The entire schema is defined and applied via Python `psycopg2` in `scripts/setup_db.py`.

## Core Tables

### 1. `sources`
Holds the parent document context.
-   **id** (UUID, PK): Unique identifier.
-   **url** (TEXT, UNIQUE): The full URL of the OpenMetadata page.
-   **title** (TEXT): Extracted page title.
-   **section_category** (TEXT): High-level category (e.g., 'connectors', 'deployment').
-   **raw_content** (TEXT): The full cleaned markdown of the page.
-   **is_active** (BOOLEAN): Defaults to TRUE. Used to soft-delete or hide outdated pages.

### 2. `documents`
Holds the chunked content for vector search.
-   **id** (UUID, PK): Unique identifier.
-   **source_id** (UUID, FK): Links back to the `sources` table with `ON DELETE CASCADE`.
-   **content** (TEXT): The ~2000 character parsed paragraph/code block.
-   **embedding** (VECTOR(384)): The mathematical representation generated by `all-MiniLM-L6-v2`.
-   **chunk_index** (INT): The sequential order of this chunk on the parent page.

### 3. `conversations` & `messages`
For API state tracking (if persistence is enabled beyond in-memory).
-   **conversations.id** (UUID, PK).
-   **messages.role** (TEXT): 'user', 'assistant', 'system'.
-   **messages.content** (TEXT): The chat text.

## Indexes for Performance

To handle thousands of text chunks in milliseconds, we rely on specialized PostgreSQL indexes:

1.  **HNSW Index**: 
    ```sql
    CREATE INDEX idx_documents_embedding 
    ON documents USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);
    ```
    Hierarchical Navigable Small World (HNSW) is significantly faster than Exact Nearest Neighbor (IVFFlat) for vector similarity searches at scale.

2.  **GIN Full-Text Index**:
    ```sql
    CREATE INDEX idx_documents_content_fts 
    ON documents USING GIN (to_tsvector('english', content));
    ```

## Core RPCs

The application makes RPC (Remote Procedure Call) requests to the database via Supabase.

### `match_documents`
The backbone of the semantic search.
-   **Input**: Query embedding (`VECTOR(384)`), Match Threshold (`FLOAT`), Limit (`INT`).
-   **Operation**: Calculates Cosine Distance (`d.embedding <=> query_embedding`).
-   **Output**: A joined table of document chunks and their parent source URLs, strictly ordered by highest similarity.

### `keyword_search`
The deterministic fallback.
-   **Input**: Search string (`TEXT`), Limit (`INT`).
-   **Operation**: Uses `ts_rank` to score the document against the query using `websearch_to_tsquery`. It naturally handles logical operators ("Snowflake NOT Docker").
-   **Output**: Ranks relevant chunks using traditional linguistic word matching.
